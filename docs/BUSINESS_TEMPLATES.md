# ビジネス用テンプレート

すべて通常のMarkdownで編集でき、追加の描画ツールは不要です。カタログは予約管理サービスの**架空の仮説**で統一しています。実際の顧客・競合・数値に流用せず、対象期間と根拠を確認して置き換えます。

## カスタマージャーニーマップ

`journey` を指定し、段階を列、観点を行にした表を書きます。対象者・達成したい目的・対象場面を表の上に短く示します。行は行動、接点、考え、感情、課題、改善機会など。4〜5段階・5〜6観点、1セル1〜2行が目安です。観点や段階の数は固定ではありませんが、増える場合はフェーズごとに分割します。

```markdown
<!-- _class: journey -->

# 初回予約までの体験

対象：初めて予約する人 ／ 目的：希望日時で予約する（仮説）

| 観点 | 認知 | 比較 | 申込 | 初回利用 |
|---|---|---|---|---|
| 行動 | 紹介を見る | 条件を調べる | 日時を選ぶ | 店舗へ行く |
| 感情 | 期待 | 迷い | 不安 | 安心 |
| 課題 | 利用像が曖昧 | 総額が不明 | 入力が多い | 場所が不明 |
| 改善機会 | 利用例を載せる | 総額を示す | 入力を減らす | 地図を送る |
```

感情を都合よく決めつけず、インタビューや観察と照合します。改善案は体験の事実とは分けて記録します。[NN/gのジャーニーマップ解説](https://www.nngroup.com/articles/customer-journey-mapping/)を参考に、目標と行動を段階に沿って整理する構成です。

## リーンキャンバス・ビジネスモデルキャンバス

両方とも `canvas` を使い、次の順で**9項目の箇条書き**を書きます。見出しは各項目の最初の段落に `**見出し**` とし、本文は空行を挟んで2スペース以上インデントします。HTMLによるセル結合は不要です。1・4・7番は縦長、8・9番は下段の横長枠です。

| 順番・位置 | リーンキャンバス | ビジネスモデルキャンバス |
|---|---|---|
| 1：左・縦長 | 課題（既存の代替も） | 主要パートナー |
| 2：左中・上 | 解決策 | 主要活動 |
| 3：左中・下 | 主要指標 | 主要リソース |
| 4：中央・縦長 | 独自の価値提案 | 価値提案 |
| 5：右中・上 | 圧倒的な優位性 | 顧客との関係 |
| 6：右中・下 | チャネル | チャネル |
| 7：右・縦長 | 顧客セグメント（初期顧客も） | 顧客セグメント |
| 8：下段・左 | コスト構造 | コスト構造 |
| 9：下段・右 | 収益の流れ | 収益の流れ |

```markdown
<!-- _class: canvas -->

# リーンキャンバス

- **課題**

  顧客が困っていること。
- **解決策**

  課題に対応する最小の仕組み。
```

上は先頭2項目だけの記法例です。実際にはカタログの9項目全体をコピーしてください。枠を増減すると意味と配置が崩れるため、項目数は9に固定しています。本文は短い2〜4行、見出しは2行までが目安です。未検証なら「仮説」、不明なら「要調査」と書き、無理に埋めません。長い説明は別スライドへ分けます。

リーンキャンバスは課題・顧客・解決策の仮説を整理し、ビジネスモデルキャンバスは価値を届けて収益を得る仕組みを整理します。[Ash Mauryaによる課題重視の説明](https://www.leanfoundry.com/articles/love-the-problem-not-your-solution)と[Strategyzerによるビジネスモデルの説明](https://www.strategyzer.com/library/what-is-a-business-model)を参照してください。本テンプレートは独自のMarkdown/CSS実装と架空の記入例です。

## SWOTとクロスSWOT

SWOTは `cards card-top` の4項目で、S・Wを内部要因、O・Tを外部要因として整理します。良い／悪いだけで分類せず、誰のどの目的に対する評価かを先に決めます。各要因にS1・W1などのIDを付けると、次の施策へつなげやすくなります。

クロスSWOTは `matrix matrix-neutral` と3列×3行のMarkdown表（見出しを含む）を使います。列がS/W、行がO/Tです。SO・WO・ST・WTそれぞれに、元の要因IDと具体的な施策を書きます。`matrix-neutral` は既存の優先順位マトリクスの象限強調を解除し、本文を左揃えにする修飾です。

施策は分析の結論ではなく検証対象です。効果・担当・期限が必要なら、既存の `action` や `risk-action` のスライドへ分けます。

## 競合分析・施策の優先順位

競合分析は `comparison-table` を使い、3案・4〜5軸程度にまとめます。直接競合に加え、手作業や現状維持などの代替も含めます。実在サービスの価格・機能を記載する場合は最新の一次情報を調べ、確認日と出典を残してください。自社案だけ評価条件を緩めないでください。

施策の優先順位は `dense` の表を使います。作例の評価値は到達人数×効果×確信度÷工数です。確信度80%は0.8として計算します。到達人数の期間、効果の尺度、工数の単位を揃え、0工数は計算しません。効果は作例では1＝小・2＝中・3＝大という独自の尺度です。これは合意形成の補助であり、順位を自動決定するものではありません。依存関係・必須対応・実行可能性も併せて確認します。Markdownの表は自動計算しないため、変更後に数値を検算してください。

## AI Agentによる作成・確認

- 目的に必要なパターンだけ選び、7種類すべてを完成資料へ追加しない。
- 未検証の顧客感情、市場動向、競合情報、事業指標を事実として書かない。
- キャンバスは9項目と順番、ジャーニーは段階と観点、クロスSWOTは要因IDの対応を確認する。
- 余白を減らす前に、1セルの文章を短くする。分割する場合も表題・対象・単位を繰り返す。
- 新レイアウトも全体の `theme:` に追従する。背景や文字の色を本文に直書きしない。
- 静的チェッカーとブラウザで、内容の欠落・枠外へのはみ出し・目次リンクを確認する。
