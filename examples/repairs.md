# 改善例：何を見て、どう直すか

[修正前](repairs-before.md)は意図的に問題を含む検証用サンプルです。そのまま配布しないでください。[修正後](repairs-after.md)は、情報を残しながら配置と参照を直した例です。

| 問題 | 観察・検出 | 修正 | 判断理由 |
|---|---|---|---|
| 7枚のカードを1スライドに置く | 静的チェックの `item-count`、表示で高さを確認 | 前提4項目と実行3項目の2枚へ分割 | 文字の縮小や項目の削除をせず、内容の役割で分ける |
| 上揃えと中央揃えが二重指定、タイトルも長い | `conflicting-modifiers`、タイトルと本文の距離 | `card-top` に統一し、タイトルを結論に短縮 | 説明量が異なるカードは上端がそろうと読みやすい |
| 出典領域だけがあり、出典の設定がない | `missing-source` | `_footer` に例示用データであることを明記 | 数値を本物の計測結果と誤解させない |
| ページを増減して参照先が存在しない | `page-link`、HTMLのリンク確認 | 表示する番号とリンク先を更新 | ページ番号は自動更新されない |

## 実行

```bash
python3 tools/check_slides.py examples/repairs-before.md --json
python3 tools/check_slides.py examples/repairs-after.md --strict --json
```

最初のコマンドは意図して終了コード1になります。2つ目は0になります。未修正例を「通るように」チェックから除外・緩和するのではなく、検出した理由を読んで直します。

見た目は利用可能なMarp環境で両方を書き出し、同じサイズで比較します。機械的に通っても、文章の意味、視線の流れ、図の読める大きさは人やAgentが画面を見て判断します。

## 図・画像を直すとき

- スクリーンショットのボタンが切れているなら、`fit-cover` から `fit-contain` に変更する。余白を減らすために操作箇所を切り落とさない。
- 図のラベルが小さいなら、枠を端まで広げる前に図を分割するか、`image-detail` で全体と拡大を示す。
- 表が横に余っているなら `comparison-table` や `dense` の共通設定を使う。セルごとにHTMLの幅指定を付けない。
- 長いタイトルでも結論を削れないなら `title-long` で2行分を確保する。3行以上は補足を本文へ移す。

新しい改善例を追加するときは、問題・検出方法・修正・判断理由を記録します。再現用の文章・数値・画像は公開可能なものに置き換えてください。
